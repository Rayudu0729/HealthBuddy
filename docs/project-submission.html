Project title

Bindu — Standalone Safety and Accessibility Wearable

Problem statement

Older adults living independently may be unable to request help promptly after a fall or emergency. Blind and low-vision users need accessible feedback about obstacles, while caregivers need to know when a safety wearable has been removed. Bindu aims to address these situations through one wrist-worn device combining local vibration and sound warnings with standalone cellular caregiver communication.

Target users

Older adults living independently, blind and low-vision adults, and their family caregivers. Each user can enable the functions relevant to their needs.

Abstract

Bindu is a standalone 4G wrist-wearable project that brings together personal safety, accessibility and caregiver communication. The planned device combines a physical SOS button, motion-based fall detection, watch-removal alerts and a gesture-activated obstacle-awareness mode.

In obstacle mode, the user raises the forearm so a distance sensor faces forward and performs a deliberate wrist gesture. Vibration pulses increase in frequency as an obstacle approaches, with an optional audible warning and distinct mode confirmations. Hand bending relative to a stationary forearm may require an additional sensor; this interaction will be validated through wearable mockups.

The planned electronics use an ESP32-S3 controller, motion and distance sensors, haptic feedback, contact sensing and an LTE modem. Local obstacle warnings will operate independently of the cellular connection. SOS and confirmed removal events will reach a self-hosted backend over Wi-Fi or LTE data; the backend will request caregiver SMS through httpSMS and a dedicated Android gateway phone. The wearer does not need a nearby phone, but remote delivery depends on internet connectivity and gateway availability. Location sharing, vitals and Telugu/Hindi voice interaction are planned extensions.

Development will progress from individual subsystem tests to an integrated PCB and a custom wrist enclosure. Evaluation will measure false alarms, obstacle-detection limits, gesture reliability, alert delivery and power consumption. Bindu is intended to supplement existing mobility aids; it does not establish that a path is clear or guarantee fall prevention.

Working prototype

The repository currently contains an ESP-IDF/FreeRTOS firmware scaffold with event dispatch, task priorities, power-mode state and separate components for fall detection, alerts, sensors, voice and synchronisation. Hardware input functions and external integrations are currently stubs. Firmware compilation and operation on the selected controller have not yet been verified in this project review.

The XIAO ESP32-S3 Plus controller and MPU6050 motion sensor have been ordered; receipt is not yet confirmed. Physical SOS input, real sensor readings, cellular delivery, obstacle feedback, wrist-gesture activation and watch-removal detection remain to be integrated and tested. There are no measured detection-accuracy, alert-latency or battery-life results yet.

The first end-to-end milestone is a deliberate SOS-button press reaching the backend over LTE data while Wi-Fi is unavailable, followed by caregiver SMS delivery through httpSMS and the Android gateway. Subsequent milestones add motion testing, obstacle warnings and removal/restoration alerts before PCB and enclosure integration.

Tech stack

Firmware: C, ESP-IDF, FreeRTOS, I²C, UART and cellular AT-command integration. Frontend: React, TypeScript and Vite. Backend: Node.js, TypeScript and Express, with PostgreSQL and Server-Sent Events for dashboard updates. SMS: httpSMS REST API and a dedicated Android gateway phone. Deployment: container images on the team's existing Kubernetes VM, HTTPS ingress and persistent database storage. This architecture is selected; implementation and deployment are pending.

Hardware

Ordered: XIAO ESP32-S3 Plus and MPU6050. Planned: VL53L1X distance sensor, LTE modem and antennas, vibration motor and driver, buzzer, SOS/cancel controls, wrist-contact sensing, protected rechargeable battery, charging/power circuitry, custom PCB, strap and enclosure. Additional hand-bend sensing and GNSS will be selected after subsystem evaluation.

Dependencies

Open-source React/Vite, Node.js/Express and PostgreSQL; ESP-IDF/FreeRTOS and hardware drivers; existing Kubernetes VM capacity, persistent storage and HTTPS access; an httpSMS account/API credential; and an Android gateway phone with internet, the httpSMS app and active SMS-capable SIM. The hosted httpSMS free plan currently allows up to 200 sent/received SMS per month. Software subscriptions are avoided, but existing infrastructure, SIM/data/SMS, hardware and fabrication may have costs. API acceptance is not proof of handset delivery or caregiver acknowledgement. No paid speech API or browser background-push service is included.

Planned demonstration

  • Physical SOS sends a caregiver alert with Wi-Fi unavailable.
  • A deliberate wrist gesture activates obstacle mode; proximity changes vibration pulses and optionally triggers sound.
  • Confirmed watch removal alerts the caregiver; stable restored contact generates a worn-again update.
  • Controlled motion recordings evaluate fall detection and false alarms before automatic notification is enabled.
